# Настройка среды и совместная работа (IntelliJ IDEA)

Этот гайд — для владельца мода. Он описывает, как поднять проект в IntelliJ IDEA,
запустить мод в игре и работать над кодом вместе с Arena-агентом.

---

## 0. Важно: проект уже готов — создавать с нуля не нужно

В репозитории уже лежит **полный Gradle-проект** (Minecraft 1.21.11 + NeoForge
21.11.45). «Создать проект в IntelliJ» в нашем случае = **открыть этот репозиторий**.
Не надо делать новый проект через мод-генератор — иначе он разойдётся с репо.

---

## 1. Что понадобится

| Компонент | Что делать |
|---|---|
| **IntelliJ IDEA** | Community Edition достаточно. https://www.jetbrains.com/idea/download/ |
| **JDK 21** | Темurin 21. Проще всего поставить прямо из IntelliJ (шаг 4б) или отсюда: https://adoptium.net/ |
| **Git** | Для работы с репозиторием. https://git-scm.com/ |

> Minecraft 1.21.11 требует именно **Java 21** (не 17, не 25).

## 2. Получить код

Способ А — через IntelliJ:
1. **File → New → Project from Version Control…**
2. URL: `https://github.com/fedandermir-art/True_Space_Mod.git`
3. Указать папку, куда клонировать, → **Clone**.

Способ Б — через терминал:
```bash
git clone https://github.com/fedandermir-art/True_Space_Mod.git
```

---

## 3. Первое открытие и синхронизация Gradle

1. Открыть папку проекта в IntelliJ (File → Open → выбрать папку).
2. IntelliJ сам подхватит `build.gradle` и начнёт **Gradle Sync**.
3. **Первый синк долгий** — скачивает Gradle 9.2.1, NeoForge, Minecraft, все
   зависимости. Это нормально и занимает **до часа** (один раз). Не прерывай.

Признак успеха — внизу появится панель Gradle без ошибок.

---

## 4. Настроить JDK 21

1. **File → Project Structure → Project → SDK**.
2. Если JDK 21 нет: **Add SDK → Download JDK → Temurin → 21**.
3. Убедись, что **Gradle JVM** тоже использует JDK 21:
   **Settings → Build Tools → Gradle → Gradle JVM → Project SDK (21)**.
4. Применить, перезапустить синк (кнопка «слоник» в панели Gradle).

---

## 5. Запуск мода

Способы запустить клиент с модом:
- **Через Gradle:** `./gradlew runClient`
- **Через IntelliJ:** в панели Gradle → `TruespaceMod → Tasks → neoforge → runClient`
  (или выбери готовую run-конфигурацию `runClient` в списке конфигураций).

> EULA принимается только для **выделенного сервера** (`runServer`): тогда нужно
> в `runs/server/eula.txt` поставить `eula=true`. Для клиента это не требуется.

---

## 6. Полезные команды Gradle

```bash
./gradlew build      # собрать jar: build/libs/truespace-0.1.0.jar
./gradlew runData    # сгенерировать рецепты/локализацию в src/generated/resources
./gradlew runClient  # запустить клиент в dev-среде
./gradlew runServer  # запустить выделенный сервер
```

## 7. Включить автоматическую сборку (CI) — у тебя есть права

GitHub Actions workflow уже написан в [`ci/build.yml`](../../ci/build.yml), но агент
не может положить его в `.github/workflows/` (нет разрешения). Ты — владелец, у тебя
разрешение есть. Включи CI, чтобы каждое изменение автоматически проверялось на
компиляцию:

1. В репозитории на GitHub: **Add file → Create new file**.
2. Имя файла: `.github/workflows/build.yml`.
3. Вставь содержимое [`ci/build.yml`](../../ci/build.yml).
4. **Commit changes**. После этого каждый push будет собирать мод и отдавать jar-артефакт.

## 8. Как мы работаем вдвоём (порядок)

1. **Сначала реестр, потом код.** Каждый новый предмет/блок/машина сначала описывается
   в `content/registry/` (с реальной основой и источником), затем пишется Java-код.
   Это наше железное правило — чтобы ничего не забыть и не рассинхронить.
2. **Я пишу и пушу** в ветку `arena/01a0783c-true-space-mod`; ты `git pull` и видишь
   мои изменения в IntelliJ.
3. **Ты пишешь** у себя — и пушишь. Перед работой делай `git pull`, чтобы не было
   конфликтов.
4. Договоримся, кто что пишет, чтобы не редактировать один файл одновременно.

### Варианты git-схемы (обсудим в чате)

- **Простая:** оба пушим в одну ветку `arena/01a0783c-true-space-mod` (быстро, но
  есть риск конфликтов).
- **Через PR:** ты работаешь в своей ветке (например, `dev/<ник>`), пушишь и
  открываешь Pull Request в `arena/...`; я проверяю и мержу.

## 9. Частые проблемы при первом запуске

| Проблема | Решение |
|---|---|
| «No matching toolchain / SDK 21 not found» | Поставь JDK 21 (шаг 4), перезапусти синк |
| Синк висит часами | Это норма для первого раза; дай закончить, не убивай процесс |
| Не хватает памяти Gradle | В `gradle.properties` стоит `-Xmx2G`; при необходимости подними |
| Не видно текстуры/предмета | `./gradlew runData` перегенерировал бы ресурсы — но у нас они уже закоммичены в `src/generated/resources` |
| Ошибка из-за `.github/workflows` при push | См. шаг 7: у агента нет прав, у тебя — есть |
