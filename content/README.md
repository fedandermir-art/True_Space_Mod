# Content Registry (реестр контента)

Это **дизайнерский реестр всего контента мода** — «мозг» проекта, чтобы ничего не забыть.
Он не загружается игрой, но является источником истины для баланса, крафтов и реализма.

> Правило проекта: **нет реальной основы — нет контента.**
> У каждой записи должно быть поле `realWorld` (на чём основано + источник + реальные числа).

## Структура

```
content/
├── README.md                  ← этот файл
├── schema/
│   └── registry.schema.json   ← JSON Schema записи (валидирует формат)
└── registry/
    ├── _index.json            ← сводка по категориям и статусам
    ├── materials.json         ← руды, металлы, сплавы
    ├── fluids.json            ← газы, топлива, окислители
    ├── machines.json          ← машины-процессы (Байер, Холла-Эру, Кролл, Сабатье...)
    ├── components.json        ← детали и агрегаты (двигатели, насосы, авионика...)
    ├── systems.json           ← сквозные системы (электричество, давление, тепло...)
    └── ...                    ← далее: items, blocks, worlds, mobs
```

## Формат записи

Каждый файл категории — объект `{ "category", "description", "entries": { "<id>": { ... } } }`.
Описание полей — в `schema/registry.schema.json`. Ключевые поля:

| Поле         | Назначение |
|--------------|------------|
| `id`         | Уникальный id (для игрового контента = `truespace:<id>`) |
| `type`       | material / item / block / fluid / machine / component / world / mob / mechanic / system |
| `status`     | `planned` → `designed` → `implemented` / `placeholder` |
| `name`, `description` | Локализованные названия (en + ru) |
| `realWorld`  | `basis` (что это в реальности), `source` (ссылка), `data` (реальные числа) |
| `recipe`     | Проектное описание процесса: машина, входы, выходы, побочные продукты, примечание |
| `depends` / `related` | Зависимости и перекрёстные ссылки на другие id |

## Рабочий процесс добавления контента

1. **Сначала реестр**: добавь запись в нужную категорию, укажи `realWorld` и `recipe`.
2. **Потом код**: зарегистрируй предмет/блок/машину в `src/main/java/com/truespace/init/`.
3. **Потом датаген**: сгенерируй рецепты/локализацию/модели (`./gradlew runData`) так, чтобы они **совпадали** с `recipe` в реестре.
4. Отметь `status: implemented`.

Связь «реестр ↔ игровые JSON ↔ код» подробно описана в [`docs/content/registry.md`](../docs/content/registry.md).
